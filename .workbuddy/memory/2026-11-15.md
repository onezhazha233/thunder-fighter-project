## xenomorph attack_6：摆动子弹的反弹改用 dir

**原代码问题**：反弹用 `hspeed *= -1` / `vspeed *= -1`，但子弹位置是靠
`ox/oy` 手工推进再赋给 `x/y` 的，`hspeed/vspeed` 从没设置过（恒为 0），
所以整个 `if(bounced < 3){...}` 分支实际上什么也没做。

**改法**：反弹改 `dir` 的角度镜像
- 左右边界：`dir = 180 - dir`（水平分量反转）
- 上下边界：`dir = -dir`（垂直分量反转）

配套三处修正：
- 边界判定改用 `ox/oy` 而不是 `x/y` —— `x/y` 含摆动偏移，会提前误判
- 反弹后 `clamp` 修正基准点，避免卡出界
- 反弹时 `time = 0` 重置摆动相位。因为摆动轴是 `dir+90`，`dir` 一变轴就变，
  不重置会让 `x/y` 在反弹当帧跳变（幅度最大 40px）

**验证**（模拟 400 帧，初始 dir=-90、spd=6、720×1280）：
- 第 99 帧碰顶 → dir 转 90
- 第 313 帧碰底 → dir 转 -90
- 全程位置不出界

**顺带修复**：attack_6 原本没有 `end_attack()`，而 `fixed_sequence = [a6]`，
攻击会永远收不了尾。已补 `At(120, end_attack)`。

**注意**：初始 `dir = -90` 是垂直向上，只有上下反弹、碰不到左右。
要斜向弹跳需改初始 dir。

## seq_enemy_boss_mini_og3_die 补死亡淡出

xenomorph 的死亡序列原本**完全静态**：26 个图层、每条 RealTrack 只有 1 个关键帧、
无曲线、无 ColourTrack，150 帧里除了停着什么都不做。

参照 `seq_enemy_boss_mini_og2_die` 的做法（每个 GraphicTrack 下挂一条
`blend_multiply` 颜色轨），给全部 26 个图层各插入一条：

| 关键帧 | Key | Colour |
|---|---|---|
| 1 | 0 | `0xFF808080` 不透明 |
| 2 | 120 | `0xFF808080` 不透明 |
| 3 | 149.9999 | `0x00808080` 全透明 |

即前 80% 保持不变、最后 30 帧淡出，与参考序列的 96/120 比例一致。

- 只改 `seq_enemy_boss_mini_og3_die.yy`，`_b` 备份未动
- `length` 保持 150，`playback` 保持 0（单次）
- 26/26 图层结构校验通过，JSON 可正常解析

未做：参考序列 main 组还有 position/rotation/scale 三条轻微浮动曲线
（幅度仅 ±7px），视觉影响很小，暂未添加。

**格式注意**：GMS 的 .yy 用紧凑 JSON + 每个对象尾逗号。往数组里插对象时，
对象内部尾逗号和对象之间的分隔逗号都要有（`{...,},`），少一个就解析失败。

### 追加：组件散开与抖动（按组定向 + 错峰）

在淡出之外给 26 个 GraphicTrack 加了变换动画，散开方向**按部件所属组朝外**，
不再随机：

| 组 | 方向 | 起始帧 |
|---|---|---|
| left_up | (-1,-1) | 30 起，组内每个 +5 |
| right_up | (1,-1) | 42 起 |
| left_down | (-1,1) | 56 起 |
| right_down | (1,1) | 68 起 |
| main 直属 | center/bottom 向下、center_up 向上 | 78 起 |

组内再按索引每件 +5 帧错峰，整体形成从四角到中心的波浪。
旋转 ±60°、缩小到 0.35~0.72，与散开同步启动。

**抖动只在 main 上**：x/y 双轴随机方向，每 3 帧换一次，共 19 次铺满 60 帧，
60 帧归位，之后整体下沉 9px 到 150 帧。坐标必须是整数且绝对值 ≤10。

```
(-2,10) (-8,-5) (8,2) (-7,-2) (-4,4) (3,4) (4,-3) (-2,-4) (3,-2) (0,-3)
(3,-1) (-2,0) (1,-2) (1,1) (-2,0) (1,0) (0,1) (0,-1) (0,1)
```

- 幅度按 10 → 1 指数递减（`10*(0.1**(i/18))` 取整）
- 方向自定义随机，但相邻两次夹角 >60°，否则看起来像原地卡顿
- 按八方向顺序轮转会被看成"转圈"，已改成随机
- 搜索 seed 时要求 x/y 偏移总和 ≤6，避免整段抖动带方向性偏向
- 部件自身不抖动

### 追加：小零件开头快速崩解

按实际贴图面积筛选（< 5000 px²），7 个实例改为 0~14 帧内飞出并消失：

| 部件 | 尺寸 | 面积 | 实例数 |
|---|---|---|---|
| up | 23×79 | 1817 | 2 |
| center_up | 40×57 | 2280 | 1 |
| engine | 49×63 | 3087 | 2 |
| down_gun | 44×92 | 4048 | 2 |

`down`（36×80, 2880）虽然面积也小，但用户要求保留常规节奏，已从名单排除。
判据是 sprite 尺寸而非图层名，注意 `down_gun` 含 "down" 但不是同一个部件。

**错开崩解**：7 个零件每隔 2 帧起一个，各自飞 **30 帧**（`SPAN=30`）：

| 部件 | 起 | 止 | 视觉偏移 |
|---|---|---|---|
| down_gun(左) | 0 | 30 | (-117,**117**) |
| down_gun(右) | 2 | 32 | (119,**119**) |
| up(左) | 4 | 34 | (-152,152) |
| engine(左) | 6 | 36 | (-125,**-125**) |
| up(右) | 8 | 38 | (152,152) |
| engine(右) | 10 | 40 | (111,**-111**) |
| center_up | 12 | 42 | (0,-150) |

垂直方向按部件类型覆盖，水平仍按组朝外：
- `engine` 强制朝上（原本在 left_down/right_down 组里是向下的）
- `down_gun` 强制朝下（原本在 left_up/right_up 组里是向上的）
- 颜色轨关键帧跟随各自的起止时间

**移出 main 组**：改为「本体 + 副本」交接，而不是直接搬走。

- **本体**留在原组内，position/rotation/scale 恢复静态，颜色在各自 start 帧归零
  （`0 不透明 → start 不透明 → start+0.5 透明`），所以散开前它一直跟着 main 抖
- **副本**是 deepcopy 后挂到顶层，颜色 `0 透明 → start 显形 → end 淡出`，
  位置从本体在 start 帧的视觉位置起算，然后飞出

**关键规则（序列变换模型）**：

- 部件的**自身 scale 只翻转贴图，不影响自身 position**。position 在父空间里是绝对值。
- 只有**父组**的 scale 会乘到子部件的坐标上。
- 所以左右镜像的正确表达是「position 取正负 + scaleX=-1」，
  不能用「position 取负 + scaleX=-1」——那样会把位置翻两次，右侧零件跑到左边。

证据：`seq_blade_a_idle` 里同一张贴图成对出现，`spr_blade_a_wing_edge`
一左一右分别是 `x=-48, sx=-1` 和 `x=+48, sx=+1`；`spr_blade_a_tail` 是
`x=-4, sx=-1` / `x=+4, sx=+1`。位置符号决定左右，sx 只负责翻贴图。

因此副本（顶层、无父组）的位置直接写视觉坐标：
`px = sx*x0 + main_offset(start)`，scale 写 `s0x*sx` 保住镜像。
本体在组内的视觉位置同样是 `sx*x0 + main_offset`，两边天然对齐。
逐件验证 7 个交接点，坐标差全为 0。

最终结构：33 个部件（26 本体 + 7 副本）、33 条颜色轨。
顶层顺序 `[main, 7 个副本]`，副本绘制在主体之上。

- position/rotation/scale 只有 0 和 14 两个关键帧，飞出 150~220px、旋转 ±140°、缩到 0.1~0.3
- 颜色轨改为 0 / 6 / 14，即 14 帧内淡完
- 其余 15 个部件保持原节奏（30~108 错峰散开、120~150 淡出）
- 方向沿用组朝外逻辑，镜像组仍乘 scaleX 符号

时间线：0~42 小零件逐个脱离并飘出（SPAN=30、GAP=2，7 件分别在 0/2/4/6/8/10/12 帧起手）
→ 0~60 整体抖动 → 30~108 主体错峰崩解 → 120~150 淡出。

要点：
- 偏移**叠加在原值上**，否则部件初始布局会乱
- scale 保留原符号（镜像组 -1），乘缩小系数后仍为负
- **镜像组的坐标是翻转的**：`right_up` / `right_down` 的组 scale 是 `(-1,1)`，
  局部 +x 在视觉上是向左。给它们 +87 的偏移会让右侧部件也朝左飞，
  表现为"整体向左"。方向必须乘祖先组的 scaleX 符号再取反。
- 旋转方向同理乘符号，保证镜像组与非镜像组的旋转观感一致
- 随机量固定种子 `20261115`

**副作用**：文件从紧凑格式重排为展开格式，152KB → 573KB。
JSON 语义一致（round-trip 校验通过），GMS 打开会略慢。
阶段备份：`/tmp/og3_die_stage1.yy`（仅淡出）。




### 副本改为硬切出现

原来副本颜色轨是 `(0, 透明) → (start, 实心)`，在整数帧上采样就是一串中间 alpha，
观感是"慢慢渐入"。改成：

- 副本：`(0, 透明) (start-1, 透明) (start, 实心) (end, 透明)` —— 整数帧采样下
  第 start-1 帧仍全透明、第 start 帧直接 255，等于硬切；后面的淡出保留。
- 本体：`(0, 实心) (start, 实心) (start+0.05, 透明)` —— 交接帧后 0.05 帧内消失，
  被副本在同一位置的实心图像盖住，看不出接缝。

**要点**：序列渲染是按整数帧采样关键帧的，所以"渐变"只会出现在跨越多帧的
两段关键帧之间。想要硬切，就把两个关键帧压到相邻整数帧（或小于 1 帧的间隔）。
