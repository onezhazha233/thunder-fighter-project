## 排查：准备界面切换到 subweapon_helix_piercer c/d 后子弹多发

- 结论：并非一次齐射 4 发，而是切换后连续两轮齐射叠加。第一轮按 weapon_level=0 打 2 发，3 帧后按 level=3 打 3 发；两轮各有一发从 -90° 出发、同起点同相位，视觉上并成一条，所以看起来是 4 条螺旋而非 3 条。
- 链路：equipment_select/Other_10.gml `refresh_preview()` else 分支只更新 `preview_inst.subweapon`、`alarm[0]=1`、`SetRampage(false)`，并给自己 `alarm[0]=3`；equipment_agent/Alarm_0.gml 重建 subweapon_inst 后只 `SetEnabled(enabled)`，未同步 weapon_level；emitter_player/Create_0.gml 的 `weapon_level=0` + `alarm[0]=1` 让新实例立刻开火；3 帧后 equipment_select/Alarm_0.gml 的 `SetWeaponLevel(3)` → emitter_player `SetLevel()` 内 `alarm[0]=1` 再打一轮。首次进入界面正常，因为那时 preview_inst.enabled=false，重建后发射器是禁用的。
- c/d 特有的可见性：Other_10.gml 用 `2+(weapon_level==3)` 决定发数（a/b 恒 2 发）；bullet_player_helix_piercer 的 auto_destroy=false、dist_max 取屏幕对角线，子弹驻留约 170 帧，历史齐射全部叠在画面上。
- 次要隐患：c/d 的 Other_11.gml rampage 齐射后 `alarm[2]=9`，Alarm_2.gml 会追加第二波 3 发；emitter_player/SetRampage(false) 未清 alarm[2]。预览每 450 帧有 200 帧暴走（equipment_select/Step_0.gml）。

### 建议修复（未实施）
1. 最小改法：`refresh_preview()` else 分支在 `preview_inst.alarm[0]=1` 前加 `preview_inst.enabled=false;`，由 3 帧后的 `SetEnabled(true)+SetWeaponLevel(3)` 统一启用，只留一轮 3 发。
2. 根治：equipment_agent/Alarm_0.gml 重建实例后同步 weapon_level/rampage，且 `SetLevel` 内加 `if(weapon_level == level) return;` 避免每次刷新强制重排 alarm[0]。
3. 视情况在 SetRampage(false) 清 alarm[2]（注意 glacier 等其它武器也用 alarm[2]，需限定范围）。

## 实现：emitter_boss_xenomorph attack_1 第三组弹（贝塞尔锁定弹）

- 歼灭炮贝塞尔参考：`bullet_player_annihilator/Create_0.gml` 的 `InitBezier()` + `Draw_0.gml` 的三次贝塞尔求值：p0=发射点，p1/p2 沿 `direction` 前伸 100/300，p3=target；`b_t += track_perm(0.03)`，t>=1 后 `speed=init_v` 直线飞。`bullet_player_missile/Draw_0.gml` 是同套但终点每帧跟随目标；本项目要求的是"终点只读一次"。
- 已在 `objects/emitter_boss_xenomorph/Create_0.gml:79-153` 实现：创建时把 `_tx/_ty` 写入 `p3x/p3y` 一次，`custom_function` 内不再读玩家/鼠标；波次由 `attack_time div 60` 奇偶得 `wave_side=±1`，出射方向 ±45° 生成控制点 → 每波轮流偏左/偏右；t>=1 时按 p2→p3 切线设 `direction` 并 `speed=12` 直线飞；曲线阶段 `speed=0` 防内建移动叠加。
- 敌弹每帧钩子是 `bullet_enemy/Step_0.gml:3` 的 `custom_function()`；必须在 `with(bb){...}` 内定义方法才会绑定 self=bb（沿用该文件上半段写法），方法体内只能用 bb 实例变量，不能引用外部 var 局部变量。
- 可调参数：`wave_side*45`（偏转幅度）、`track_perm=0.03`（曲线≈34帧）、`init_v=12`（终点后速度）。若想改成"每发交替"而非"每波交替"，把 `_side` 那行的 `div 60` 换成 `div 4`。

## 跟进：每波共用同一目标坐标

- 用户自行把"每发各锁一次目标"改成 `attack_time mod 60 = 0` 时锁 `tx/ty`，波内所有子弹用 `bb.aim_x = tx; bb.aim_y = ty;`；同时把 bug 弹 `image_angle` 从 `direction - 90` 调成 `direction + 90`（用户调整，勿改回）。

## 分析：敌弹子弹池系统的难点（只分析，未实施）

- 规模：29 个 `bullet_enemy*` 对象 / 113 个事件文件 / 36 个文件调用 `MakeEnemyBullet`；敌弹内 37 处 `instance_destroy` + 外部 16 处 `with(bullet_enemy)` ≈ 53 个销毁/操作点必须改道到池回收。
- 语义冲突（硬证据）：`instance_number(bullet_enemy*)` 共 5 处——`bullet_enemy_wavering_manager/Create_0.gml:63` 每帧 `instance_number`+`instance_find` 收集圆环、`emitter_boss_laser_piano_p1:322`(≤4) / `p2:448,497`(≤8) 限流、`debugger/Draw_0:4` 显示；池化后计数含闲置实例，逻辑失效。`instance_exists` 在项目里等同"还活着"。
- 语言限制：GML 只有 `instance_deactivate_all/object/region/layer`，**没有单实例停用**；`battle_ui_pause/Create_0.gml:56` 用 `instance_deactivate_all(true)`、`Draw_0.gml:15` 用 `instance_activate_all()`，会把池一起激活。
- 生命周期：`bullet_enemy` 非 persistent（池随房间销毁）；`world`/`camera` persistent，`Anim_Step` 在 `world/Step_0`。`battle_loading` 只 prefetch 3 个激光精灵 + UI_Warmup + 序列轮播，且 `room_goto(room_battle)` 会销毁预热实例 → 预热要在 room_battle 内分帧做。
- 状态残留：Create 事件不可重入（`bullet_enemy_wavering_manager` Create 131 行），16 个 function 字段 + `custom_function` 必须在复用前重置；`bullet_enemy_ring` 的 `blt[]`、manager 的实例数组、emitter 用 `with(bullet_enemy_laser_big)` 外部驱动坐标 → id 复用会跨代串扰。
- 首帧卡顿主因不只在创建：`Anim_Step` 每帧倒序全表 + 每条 `variable_instance_set` 按字符串查变量 + 结束 `array_delete` O(n)；`bullet_enemy_star/laser()` 一次 120 发 × 3 动画 = 360 条；`CleanUp_0` 每次销毁都 `layer_sequence_create` 消失特效；纹理全在 Default 组。
- 建议路线：先做动画按 target 索引 + 特效池 + 敌弹精灵全量 prefetch（可能已覆盖大头），再只池化 `bullet_enemy_normal`，用"移出房间 + pooled 标志 + 父对象 Step/Draw 提前 exit"而非 deactivate。

## 跟进：attack_0(red_heavy) 减密/降耗方案

- 结构：attack_0 每 5 帧发 1 颗 `bullet_enemy_star`（<180 帧，共 35 颗）；180 帧后 star 减速，`time > y/15+35` 时调 `laser()`；`laser()` 每颗生成 3×20×2=120 发 `bullet_enemy_normal`（`spr_bullet_enemy_normal_2` 是 89×40 水平光条），层距 60 → 相邻重叠 29px 形成连续光带；`duration=30`。
- 更正（23:05 实测反馈）：`duration = 30` 是 **star 自己**的，不是光条的（`laser()` 是 star 的方法）。光条寿命靠离屏 `auto_destroy`，所以 `Anim_Create(blt,"speed",0,0,0,30-i,60,60)`（delay 60）是有效的"停留 60 帧后射出"阶段，不是死代码。误删它 + 删掉 x/y 定位缓动 → j 小/为 0 的光条永远停在中心不动（用户实测"很多子弹没移动"）。
- 结论：光条必须保留三段式——0~30 帧 x/y 定位缓动到 85j、停留、60 帧后 speed 缓动射出。
- 减密配方：20 层/60px → **14 层/85px**，半径 1140→1105（-3%），段长 89 仍重叠 4px，弹量 4200→2940（-30%），无需放大精灵、碰撞不变；12 层/100px + 段长 115 可到 2520，但要放大视觉。
- 削峰：`time > y/15+35` 给每颗 star 加 0~25 帧偏移，4200 发摊到多帧（单帧峰值约 200），回收也错峰。
- 结论：前两条做完峰值开销降 70~85%，很可能不需要子弹池。
